앱 주소: https://claude.ai/artifact/Aohb1epNpKS27Ab91LpC4e
데이터 저장소는 ArtifactData 도구로 다룹니다 (ToolSearch "select:ArtifactData" 로 먼저 불러오세요). 페이지 파일은 수정하지 말고 저장소 문서만 쓰세요. 코드 변경·커밋·푸시·PR 은 하지 않습니다.

분석 대상
- 프로필 문서: `profiles` 컬렉션의 `{{PROFILE_ID}}`
- 프로필 이름: {{NAME}}
- JD 링크: {{URL}}
- 사용자가 붙여넣은 JD 본문(없을 수 있음):
{{TEXT}}

절차
1. ArtifactData get 으로 `profiles/{{PROFILE_ID}}` 를 읽고(version 기억), update 로 {"state":"running","startedAt":"<지금 ISO8601 UTC>"} 를 씁니다 (if_version 사용).
2. JD 를 파악합니다. WebFetch(ToolSearch "select:WebFetch,WebSearch")로 링크를 열어 보고, 막히면(403 등) 붙여넣은 본문을 쓰거나 WebSearch(mode "extended")로 같은 공고의 제목·회사·업무·자격요건 문구를 검색 결과 스니펫에서 모읍니다. 회사명, 직무명, 주요 업무, 자격 요건, 우대 사항, 게시 시기를 정리합니다. 원문을 전혀 확인할 수 없으면 note 에 그 사실을 적고, 직무명과 회사명 기준으로 분석을 진행합니다.
3. 이 JD 를 기준점으로 삼아 WebSearch 로 조사합니다 (최근 12~18개월, 한국어·영어).
   - 국내: 이 JD 와 비슷한 직무가 어떤 이름으로 늘어나고(5~6개), 어떤 직무·업무가 줄어들거나 합쳐지는지(3~5개), 실제 공고 예시(6~10개, 회사·직함·한 줄 설명·링크).
   - 해외(미국 중심, 가능하면 1개국 추가): 수요 흐름 요약, 수치 3개, 늘어나는 직무(3~5), 줄어드는 직무(3~4), 공고 예시(4~8).
   - 요구 스킬 변화(5~8개 지표, 가능하면 설문·공고 분석 수치).
   늘어나는 직무마다 이 JD 대비 적합도(높음/중간~높음/중간/낮음~중간/낮음)와 그 이유 한 줄을 씁니다. 모든 항목에 출처 URL 을 붙이고, 출처 없는 항목은 쓰지 않습니다. 개수보다 정확성을 우선합니다.
4. `profiles/{{PROFILE_ID}}` 에 update 로 다음을 씁니다 (get 으로 최신 version 확인 후 if_version). 문서 크기는 200KB 이하로 유지합니다.
{"state":"done","finishedAt":"<지금 ISO8601 UTC>","note":"한 줄 요약(원문 확인 여부 포함)","jobs":{

5. 실패하면 {"state":"error","finishedAt":"...","note":"원인 한 줄"} 을 씁니다. 어떤 경우에도 state 를 running 으로 남기지 마세요.

규칙
- 개인정보(이름+아이디, 전화번호, 이메일 등)와 인증정보는 어떤 문서에도 쓰지 않습니다. 채용 담당자 이름·연락처는 제외합니다.
- 마크다운 기호 없이 평문으로 씁니다. 따옴표는 한국어식 ‘ ’ 를 씁니다.
- 끝나면 프로필 이름과 늘어나는 직무 수를 한 줄로 보고합니다.
